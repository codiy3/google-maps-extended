# 駅の吹き出し表示位置の追加レビュー

対象基準: `e157f7c`。担当者自身によるレビュー。

## R6 / P2: 駅名が検索欄の背後に隠れる

[PR #6の追加指摘](https://github.com/codiy3/google-maps-extended/pull/6#issuecomment-5654413014)で報告した。幅473pxで和光市を選択した際、駅名見出しは画面上のy=198〜226、検索欄の下端はy=232だった。見出し「和光市駅」は生成済みであり、文字の欠落ではなく配置の重なりだった。

[GoogleのInfoWindow仕様](https://developers.google.com/maps/documentation/javascript/reference/info-window)に自動パンとvisibleイベントが記載されている。アプリ側で地図に重ねた検索欄・駅カードの領域は別途考慮する。

## 対応

- 吹き出し表示後と検索欄・地図サイズの変更後に、自前の見出し・本文の位置を測る。
- 検索欄の下端、駅カードの上端、地図の端を使って表示領域を求め、必要な場合だけ地図を移動する。
- 自動パンとレイアウト変更の後にも再確認し、補正の重複や無制限の移動を避ける。補正は最大3回とし、通常の手動パンには追従しない。
- 吹き出しを開いたまま画面幅を変える場合は、路線全体への表示範囲変更を止め、選択駅の表示を保つ。地図の移動完了と描画後に補正する。
- 吹き出しを閉じると、監視と待機中の描画処理を解除する。

## 確認

2026-09-14、Google Maps Demo Keyで390×844と1280×900を確認。路線検索から乗換案内へ切り替えても、駅詳細・種別欄・到着時刻の状態表示を維持した。390pxの乗換案内では検索欄下端y=232.5に対して見出し上端y=262.2、本文下端y=339.0、駅カード上端y=405.1となり、上下のパネルの間に表示できた。

最初の修正では画面幅を往復した際に路線全体へのfitBoundsと補正が競合したため、上記の移動完了待ちと選択駅優先を追加してから再確認した。

`npm run check`（Biome・TypeScript）、フロント38テスト、`npm run build`が成功。Python/APIの変更はなく、PR #6の検証結果を引き継ぐ。表示位置は実ブラウザーで確認し、SDKの内部DOMクラスには依存させていない。

画面が極端に低く、吹き出しを収める領域自体がない場合は駅名を優先する。パネルを折り畳んで地図を広げられる。実時刻表の未収録という制約は変更していない。
