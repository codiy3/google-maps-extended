# 起動・表示方針

状態: 2026-09-13、ローカル起動・初期表示・PCとスマートフォンの配置の基本案をユーザーが了承。macOSでの利用を追加指定。起動スクリプト・検索・線形表示を実装。現在は静的データを利用するためFastAPIは起動しない。日時照会は未実装で、以下には今後実装する要件も含む。現在使える範囲とセットアップは[アプリのREADME](../google-maps-railway-viewer/README.md)を参照。

## 起動

1. 初回にNode.js環境、npm依存関係、uvの仮想環境、Google Maps APIキー、全国鉄道データ・時刻表を準備する。時刻表サービスに認証が必要な場合は、その設定も準備する。
2. 普段はアプリディレクトリで `npm run dev` を実行する。
3. 画面用サーバーは `127.0.0.1:5173` に固定する。FastAPIを採用する場合は同じコマンドで `127.0.0.1:8000` に起動し、必要なサーバーの準備完了後に既定ブラウザを開く。
4. ポートが使用中の場合は、別ポートへの自動変更をせず理由を表示する。
5. ターミナルで `Ctrl+C` を押すと、今回の起動コマンドが生成した画面用・API用の両サーバーを停止する。片方の起動失敗時も、もう片方を残さない。ブラウザを閉じるだけではサーバーは停止しない。
6. macOSでは、Finderでダブルクリックできる `start.command` を追加する。同じ起動処理を呼び出し、既定ブラウザで開く。配置先に空白があっても動作させる。必要な環境がない場合はセットアップ方法を表示する。

Node.jsは24.21.0に固定し、macOSでは専用の`.tools/`から起動する。`package-lock.json`をコミットし、再現時は`npm ci`を使う。

Pythonはデータの初回生成・更新・検証に利用する。追加された日時指定の所要時間比較を受け、FastAPIで時刻表照会と秘密キーを扱う案を推奨する。APIはuvの仮想環境で動かし、画面からはViteの同一オリジンのプロキシ経由で呼び出す。静的データだけで全要件を満たせる場合はAPIを省略できるため、取得元の決定後に確定する。起動操作は1コマンドにまとめる。

アプリ本体はローカルで動作するが、Google マップの読み込みにはインターネット接続と利用可能なAPIキーが必要。GitHubへのソース保存とWebサイトの公開は別作業とする。

## Pythonの分離

- uv管理のCPython 3.12.13を使用する。
- `.python-version`で実行バージョンを固定する。
- `pyproject.toml`の`python-preference = "only-managed"`でシステムPythonへのフォールバックを防ぐ。
- アプリ直下の`.venv/`に依存ライブラリを分離する。
- 依存関係を`uv.lock`に記録し、`uv sync --locked`で復元する。
- Python処理は`uv run --locked ...`経由で実行する。
- Gitには設定・コード・ロックファイルを保存し、`.venv`や秘密情報は保存しない。

## 初期画面

- 日本全体の地図と、路線名の検索欄を表示する。
- 検索前は路線を選択していない状態とする。
- 明示操作なしに現在地の取得を要求しない。

## 入力中の候補表示

- 路線名を入力すると、検索欄の直下に候補一覧を表示する。
- 候補の1段目に路線名、2段目に鉄道会社・都道府県、必要に応じて対象区間を表示する。
- 複数の県をまたぐ場合も1県に限定せず、都道府県の一覧を確認できるようにする。
- 候補のクリック・タップ、または上下キーとEnterで路線を確定する。候補の先頭を自動確定しない。
- 別の名前を入力している間も選択済みの路線名と地図は維持し、新しい候補を確定した時点で切り替える。
- 日本語入力の変換確定と路線の選択を区別する。該当なし・読み込み中・取得失敗も区別して表示する。
- 詳細は[路線検索の設計](route-search.md)を参照する。

## 検索結果

- PC: 左側に検索欄と駅一覧、右側に地図を表示する案を推奨する。
- スマートフォン: 地図と検索欄を優先し、駅一覧を下側の開閉パネルに表示する。
- 路線選択時に全体が収まる範囲へ地図を移動する。
- 初期の「全駅」表示では、選択路線の全駅に赤ピン、線路形状に緑色の線を表示する。
- 種別を選択した場合は該当する停車駅だけを赤ピンで表示し、一部停車は赤枠のピンと文字で区別する。停車の証拠があり他の便が未確認の場合も赤ピンを残し、「?」と「停車あり・一部未確認」を付ける。
- 表示対象の駅をクラスタリングせず、駅ごとに選択できるようにする。
- 地図縮小時は近接するピンが重なる可能性がある。駅一覧と拡大操作から各駅を選択できるようにする。
- 駅名ラベルは選択・ポイント時を基本とし、表示密度に応じた常時表示は別途確認する。
- ピンと駅一覧の選択を連動させ、駅名・事業者を表示する。
- 出典・データ基準日・Googleの帰属表示を読める位置に配置する。

## 列車の種類と並び順

1. 路線確定後、駅一覧の上に「列車の種類」を表示する。「全駅」を初期選択とする。
2. 普通・快速・準急などの種別や、新幹線の列車名を路線データから生成する。チェックボックスで複数を選択できる案とする。
3. 「並び順: 種別順／所要時間順」を切り替えられるようにする。「全駅」は並べ替えの対象外として先頭に置く。
4. 所要時間順を選ぶと、出発駅・到着駅・日付・出発時間帯の入力欄を表示する。時刻の精度と取得範囲に応じて、各種別の比較可能な最短乗車時間と、その便の発着時刻を表示する。
5. 「全駅」は日時指定中も路線全体を表示する。個別の種類を選び、有効な日時指定の結果がある場合は、その条件への適合を確認できた便の指定区間内の停車駅を集約する。
6. 「一部停車」の駅を選ぶと、確認できた運転日・方向・該当列車などを確認できるようにする。取得できない詳細は未確認と表示する。
7. 絞り込み時も線路形状を維持する。「全駅」では全線を表示し、個別の種類と有効な日時指定の結果がある場合に指定区間を強調する。
8. 条件未入力・不正・読み込み中・取得失敗・データ不足・期間外・便なしを区別し、古い所要時間や種類の絞り込み結果を表示しない。状態ごとの表示範囲は[選択状態と表示範囲](train-services.md#選択状態と表示範囲)に統一する。

ピンの色だけに依存せず、「共通停車」「一部停車」などの文字と形で違いを伝える。複数種別や複数便の停車駅をまとめた表示を、1本の列車がすべて停車する一覧として案内しない。

## APIキー

ローカル設定は`.env.local`、設定例は`.env.example`に置く。ブラウザ用キーは閲覧可能な性質があるため、`.env`だけで秘匿できるとは扱わず、Google CloudでHTTPリファラーと使用APIを制限する。

鉄道の種別・時刻表データは、ユーザー指定により月額0円で取得できる方式を採用する。追加の指定により、Google マップの試作確認も無料のMaps Demo Keyで進める。通常キーかDemo Keyか不明な間はGoogleへ接続しない。

初期値は `VITE_GOOGLE_MAPS_MODE=preview` とする。キーを保存しただけでは外部地図を起動せず、利用者がDemo Keyを確認して `google` に変更した場合に接続する。キーの料金体系をアプリが自動判別するものではない。取得手順とキー制限はアプリのREADMEに記載する。

時刻表サービスの秘密キーは、ブラウザ公開用の`VITE_`環境変数や静的JSONに入れず、採用したローカルAPI側の設定で保持する。データをGitへ含められるかも提供元の条件に従う。

標準APIキーの課金設定は未確認。予算通知は利用を自動停止する上限ではないため、料金対策として通知のみを保証しない。
